# C11 Harbor：零跑 C11 家庭 NAS 仪表盘

给 ARM64 NAS 与局域网手机浏览器使用。已支持电量、续航、累计里程、位置、车内温度、四轮胎压、充电状态、电池侧功率、车辆预计剩余充电时间和估算行程。用户已验证 2023 款 C11 纯电版的首次会话导入、电量和位置读取；新增温度、胎压、充电字段及长期续期待实车核对。协议依据现有 `leapauto` 的公开实现与验证记录，NAS 项目不包含 APK 或闭源 SDK。

仓库：[Herowoo/c11-harbor](https://github.com/Herowoo/c11-harbor)。镜像：`ghcr.io/herowoo/c11-harbor`，支持 ARM64 与 AMD64。

## 先跑起来

1. 在 NAS 的 Docker 管理器中创建项目目录，放入仓库中的 `compose.yaml`、`.env.example` 与 `import` 文件夹。已有项目请直接在原目录更新配置，沿用原项目名和数据卷。
2. 将 `.env.example` 复制为 `.env`，设置唯一的 `ADMIN_PASSWORD`（至少 12 位，不能保留 `CHANGE_ME`）。初次保留 `ALLOW_CONTROL=false`。
3. 在项目目录运行 `docker compose pull harbor`，再运行 `docker compose up -d`。NAS 直接下载预构建镜像，使用 Node 24 内置 SQLite，不需要本地编译或下载 npm 依赖。
4. 安卓 12 手机接入同一局域网，用浏览器打开 `http://NAS局域网IP:8088`，输入服务密码。
5. 打开“车辆接入”页面，先验证登录和只读状态。随后保持服务运行，观察航行日志是否能识别真实出行。

## 在线更新

每次向 `main` 提交代码，GitHub Actions 先运行测试，通过后构建 ARM64/AMD64 镜像并发布到 GHCR 的 `latest` 标签；`v*` 标签同时生成版本标签。提交对应的镜像还保留 `sha-<完整提交 SHA>` 标签，便于定位与回退。仓库和镜像仅包含程序，不包含 NAS 数据、会话或高德 Key。[GitHub 官方镜像发布说明](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images)

**已有离线部署只需切换一次配置**：在原项目目录替换 `compose.yaml`，保留 `.env`、项目名、`harbor-data` 卷和 `import` 文件夹。若 NAS 的管理器曾手动指定卷路径，请继续使用那个实际数据卷，不要新建空卷。

后续更新只需：

```sh
docker compose pull harbor
docker compose up -d --no-build --no-deps harbor
```

或在下载过本仓库的项目目录执行 `sh scripts/update.sh`；脚本拉取镜像、更新同一服务并检查进程健康。极空间容器管理器若支持拉取镜像并重新创建服务，也可执行等价操作。更新会短暂重启服务，挂载的数据卷保留；浏览器需要重新登录玄关服务，但无需重新导入车辆会话。[Docker Compose 更新说明](https://docs.docker.com/reference/cli/docker/compose/up/)

网页“服务与会话状态”显示运行版本、构建提交、最近读取成功时间、续期结果和网关令牌到期时间。网页本身不拥有 Docker 管理权限，实际镜像更新由 NAS 的容器管理器或上述脚本完成。

可在 `.env` 将 `HARBOR_IMAGE` 改为 `ghcr.io/herowoo/c11-harbor:0.2.1` 或已有 `sha-<提交 SHA>` 标签以固定版本。回退时换回旧标签后执行相同更新命令。本版数据库迁移只增加字段，保留旧记录、会话与密钥；重大迁移前仍应备份数据卷中的数据库和 `vault.key`。

如果 GHCR 首次发布的包尚未公开，仓库拥有者需在 GitHub 包设置中将镜像可见性设为 Public；公共容器镜像允许 NAS 匿名下载。NAS 必须能够访问 `ghcr.io`。[GitHub 容器可见性说明](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry)

如需将坐标显示为中文地址，在 `.env` 填写已有高德 Web 服务 Key 的 `AMAP_WEB_KEY`。逆地理编码由 NAS 向高德 Web 服务发起，Key 不发送给手机浏览器；没有 Key 时显示经纬度。地址结果只缓存于服务内存约一小时，不写入日志库。该接口要求经度在前、纬度在后；坐标以现有 C11 信号的 GCJ-02 口径处理。[高德逆地理编码文档](https://lbs.amap.com/api/webservice/guide/api/georegeo/)

端口可通过 `HOST_PORT` 修改。服务只适合可信家庭局域网；不要在路由器做公网端口转发。经浏览器导入会话或执行控制前，建议通过 NAS 的 HTTPS 反向代理访问，以免局域网 HTTP 流量被读取。Cookie 只允许同源访问，12 小时过期，重启服务后需重新登录网页。

## 账号接入

### 推荐：安卓导出文件，NAS 离线导入

配套 APK 名称为“NAS会话导出”，包名 `com.leapauto.app.nas`，可与原版 leapauto 并行安装。需要在这个新安装中正常完成短信登录，原安装的会话不会自动共享。登录后进入「我的 → NAS 会话导出与配对」，点击“导出 NAS 登录文件”，保存到手机 Download 文件夹。

通过 USB 把 `c11-nas-session.json` 复制到电脑，再用 NAS 文件管理器或 SMB 放到本项目的 `import` 文件夹。Compose 会把该文件夹只读挂载到容器 `/import`。网页打开 `http://NAS局域网IP:8088`，登录后点击“导入已上传的登录文件”。网页请求只传递导入动作，登录凭据由 NAS 直接读取文件，不经浏览器 HTTP 请求传输。可以保持 `PAIR_BASE_URL` 为空，无需域名或 HTTPS 证书。成功后删除手机、电脑和 NAS 中的明文文件；服务器已将会话加密保存到数据卷。

导出版到 NAS 的首次会话导入路径已由用户验证。NAS 是否能长期独立续期仍需跨过令牌有效期后观察。先保持 `ALLOW_CONTROL=false`。

### 可选：安卓客户端一次性配对

源码配套的 `leapauto` 安卓客户端提供「我的 → NAS 会话导出与配对」。先在 NAS 配置可信 HTTPS 反向代理和有效证书，确保代理保留原始 `Host`，将其完整来源地址（例如 `https://nas.example.com`，可带端口，不带路径）写入 `.env` 的 `PAIR_BASE_URL`，重启容器。手机端与 NAS 网页都必须使用这一 HTTPS 地址；Android 不会绕过证书验证。仅有局域网 IP 与自签名证书时，请先解决证书信任问题。不要把明文 8088 端口暴露到公网。

在 NAS 网页输入服务密码后，点击“生成配对码”；8 位码 5 分钟有效，最多错误尝试 5 次。安卓客户端先完成正常短信登录，再在「我的 → 配对 NAS」输入 HTTPS 地址和配对码，确认后由手机主动发送当前旧会话的 `deviceId`、手机号、账号 ID、令牌及刷新令牌。不会发送车辆操作密码、数美设备 ID、位置或 VIN。NAS 验证配对码后尝试换取网关令牌并识别唯一车辆；成功才加密保存会话。成功后配对码立即失效；失败可在有效期内重试，过期后重新生成。NAS 仍不能保证零跑后续会话续期不会触发风控，需用真实车辆只读验证。

自行构建的 APK 与原作者发布的 APK 签名不同，不能原位更新原安装。“NAS会话导出”使用独立包名和本地生成的签名；其后续更新需要复用该本地签名。

网页支持短信验证码登录，但服务端没有数美设备风控 SDK，也没有极验验证界面。短信发送也可能被风控限制。`smDeviceId` 是 Android 数美 SDK 在运行时获取的设备指纹；`leapauto` 当前正常短信登录流程未把返回值写入会话，因此已登录不代表能从会话里直接读到。没有 root 的 Release 安装通常也不能直接通过 ADB 读取应用私有数据。只有已自行取得有效 `smDeviceId` 时才尝试此入口；单独拿到该值也不保证成功，因为 NAS 发出的 `deviceId` 和手机设备环境可能不一致，且服务端仍可能要求极验。更稳妥的下一步是安卓端完成完整登录，再通过一次性配对把旧会话交给 NAS。遇极验或数美阻断时，可尝试“导入已登录会话”接入：

```json
{
  "deviceId": "你的现有安卓会话设备 ID",
  "phone": "手机号（供旧令牌续期）",
  "appVersion": "1.22.95",
  "old": {
    "accountId": "旧账号 ID",
    "token": "旧会话令牌",
    "refreshToken": "旧会话刷新令牌"
  }
}
```

这些值均为账号凭据，不要发送到聊天、贴到 GitHub、分享日志。可在自己设备上的已登录会话中提取；字段名称与 `leapauto` 的 SessionStore 相同。服务端收到后会向国内新网关交换令牌、获取车辆列表和路由；当前版本仅允许单车账号，避免选错车辆。会话用本机随机 AES-GCM 密钥加密后保存在 Docker 卷；`/data/vault.key` 必须与 SQLite 数据库一起备份。更换该密钥后旧会话无法解密。

如果旧令牌也已失效，请先从官方或 `leapauto` 安卓客户端重新登录，再导入新的会话。第一版不会尝试规避数美或极验。

## 出发按钮

完成只读验证后，将 `.env` 的 `ALLOW_CONTROL=true` 并重启容器，手机页的“开启空调”按钮才会启用。每次都要输入四位车辆操作密码并再次确认。操作密码不会写入数据库。服务端仅发送一次指令，结果显示“已执行”“失败”或“待确认”；若网络在提交后断开，绝不自动重试，避免重复执行。此控制通道尚未在用户车辆上验证。

## 航行日志的口径

每 5 分钟采集一次（可通过 `POLL_MINUTES` 在 3–30 分钟间调整）。同一车端时间戳不会重复入库。里程增加 0.2 km 以上开始估算行程；停车观察至少 5 分钟才结束。超过 30 分钟的采集缺口标为“估算·存在数据缺口”。按结束时间（中国时间 UTC+8）汇总每日里程。只保存采样字段及有效坐标，不保存原始 `signalMap`、VIN 或请求响应。样本保留 90 天，行程长期保留。此版本没有历史里程接口回填，因此离线期间的行程可能缺失。

车辆接口的 `sts` 更新频率、真实坐标和停车判定仍需在实车数据上验证；网页会同时显示车辆上报时间与 NAS 接收时间。行程是估算结果，不是精确路线或精确电耗。

服务重启时，执行中的空调指令会标记为“待确认”，不会重新发送。首次上线请先以只读模式积累几天数据，再判断自动行程分段是否符合你的实际停车方式。

## 温度、胎压与充电口径

字段映射记录在 [PROTOCOL.md](PROTOCOL.md)。胎压按 kPa 显示，告警采用车端状态，不以猜测阈值替代车端判断。电池侧功率仅在充电状态下按 `abs(电压 × 电流) / 1000` 计算，可能与充电桩显示不同。预计完成时刻使用“车辆上报时刻 + 剩余分钟”，旧数据或没有可靠车端时间时不显示完成时刻；剩余时间为 0 不单独判定充满。未上报字段显示 `--`。

刷新得到的新令牌会立即加密保存，即使接着读取车况失败也保留轮换后的凭据。网关与旧令牌刷新结果分别记录；持续读取与首次导入成功不等于永久有效，服务器仍可能要求重新登录。

## 本地验证

本机有 Node 24 时：

```text
node --test test/*.test.mjs
```

本机直接运行：设置 `ADMIN_PASSWORD` 与可写 `DATA_DIR`，然后执行 `node src/server.mjs`。`/health` 用于容器健康检查，不暴露车辆数据。

开发者需要从源码构建时：`docker compose -f compose.yaml -f compose.build.yaml up -d --build`。`node tools/preview.mjs` 提供只含模拟数据的本地页面，所有外部接口请求都会被阻止。

部署后先完成验收：能从安卓手机登录网页；读取到与你当前 `leapauto` 一致的电量和累计里程；上报时间合理；NAS 重启后历史日志仍在；断网时显示旧数据。完成这些再开启空调控制。ESP32 和玄关专用显示屏留给第二阶段。
